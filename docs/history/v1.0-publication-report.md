### One real defect found and fixed by this verification

Running the launcher under output capture exposed a genuine robustness bug in
`scripts/start-demo.ps1`. Windows PowerShell 5.1 converts **any** stderr line
from a native command into a terminating `NativeCommandError` while
`$ErrorActionPreference = "Stop"` — and `uv` writes progress to stderr. So a
perfectly successful `uv sync` could abort the launcher, for example when a
wrapper, a log capture, or CI merges the streams with `2>&1`.

Fixed by running native invocations with the preference relaxed and deciding on
`$LASTEXITCODE` (real failures remain fatal). The corrected script was then
re-verified end to end: `START_EXIT=0`, both services healthy, endpoints 200,
`stop-demo.ps1` → `PORT 8000 FREE`, `PORT 5173 FREE`. `stop-demo.ps1` already
used `Continue` and did not need changing.
